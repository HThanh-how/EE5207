\chapter{Implementation}

\section{Module Structure}

The design is implemented as a modular SystemVerilog project. Two top-level cores are provided:
\begin{itemize}
    \item \texttt{single\_cycle.sv}: Baseline single-cycle RV32I core used in Milestone~2.
    \item \texttt{pipelined.sv}: Final five-stage pipelined RV32I core with forwarding, hazard detection, and two-bit branch prediction used in Milestone~3.
\end{itemize}

The common building blocks reused by both cores are:
\begin{itemize}
    \item \texttt{register\_file.sv}: 32x32-bit register file.
    \item \texttt{alu.sv}: Arithmetic Logic Unit.
    \item \texttt{control\_unit.sv}: Instruction decoder and control signal generator.
\end{itemize}

For the pipelined implementation, the memory system is upgraded to synchronous 64~KiB BRAM-compatible models as required in Milestone~3:
\begin{itemize}
    \item \texttt{imem\_sync.sv}: 64~KiB synchronous instruction memory (BRAM-compatible) preloaded from \texttt{isa.mem}.
    \item \texttt{dmem\_sync.sv}: 64~KiB synchronous data memory (BRAM-compatible) and I/O interface.
\end{itemize}

\section{Pipelined Processor Architecture}

The pipelined processor implements a five-stage pipeline:
\begin{enumerate}
    \item \textbf{IF (Instruction Fetch)}: Fetches instruction from instruction memory using predicted PC
    \item \textbf{ID (Instruction Decode)}: Decodes instruction and reads register file
    \item \textbf{EX (Execute)}: Performs ALU operations and branch comparison
    \item \textbf{MEM (Memory Access)}: Accesses data memory or I/O
    \item \textbf{WB (Write Back)}: Writes result back to register file
\end{enumerate}

\subsection{Forwarding Unit}

The forwarding unit resolves data hazards by forwarding data from later pipeline stages to earlier stages:

\begin{itemize}
    \item \textbf{Forward from MEM stage}: Highest priority, forwards ALU result from MEM stage to EX stage
    \item \textbf{Forward from WB stage}: Lower priority, forwards register write data from WB stage to EX stage
    \item \textbf{Forwarding MUX}: Selects between original register data, MEM forwarded data, or WB forwarded data
\end{itemize}

The forwarding logic checks if the destination register of instructions in MEM or WB stages matches the source registers of the instruction in EX stage, and forwards the appropriate data.

\subsection{Hazard Detection Unit}

The hazard detection unit handles two types of hazards:

\subsubsection{Load-Use Hazard}
When a load instruction is in EX stage and a dependent instruction is in ID stage, the pipeline must stall:
\begin{itemize}
    \item Stall IF and ID stages (prevent new instructions from entering)
    \item Flush EX stage (insert bubble/NOP)
    \item Wait until load completes in MEM stage before continuing
\end{itemize}

\subsubsection{Control Hazard}
When a branch or jump instruction is mispredicted:
\begin{itemize}
    \item Flush IF, ID, and EX stages (remove incorrectly fetched instructions)
    \item Correct PC to actual target address
    \item Update branch predictor with actual outcome
\end{itemize}

\subsection{Two-Bit Branch Predictor}

The processor implements a two-bit dynamic branch predictor with Branch Target Buffer (BTB):

\subsubsection{Branch Target Buffer (BTB)}
\begin{itemize}
    \item \textbf{Size}: 256 entries
    \item \textbf{Structure}: Each entry contains:
    \begin{itemize}
        \item Tag: Upper bits of PC for matching
        \item Predicted PC: Target address for branch/jump
        \item Two-bit predictor state: Prediction confidence
    \end{itemize}
    \item \textbf{Lookup}: In IF stage, uses PC index to check BTB
    \item \textbf{Update}: In EX stage, updates BTB when branch/jump resolves
\end{itemize}

\subsubsection{Two-Bit State Machine}
The predictor uses four states:
\begin{itemize}
    \item \textbf{00 (Strongly Not-Taken)}: Predict not-taken with high confidence
    \item \textbf{01 (Weakly Not-Taken)}: Predict not-taken with low confidence
    \item \textbf{10 (Weakly Taken)}: Predict taken with low confidence
    \item \textbf{11 (Strongly Taken)}: Predict taken with high confidence
\end{itemize}

State transitions:
\begin{itemize}
    \item If prediction correct: Move toward stronger confidence (e.g., 01 → 00 or 10 → 11)
    \item If prediction incorrect: Move toward opposite direction (e.g., 00 → 01 → 11 or 11 → 10 → 01)
\end{itemize}

\subsubsection{Prediction Logic}
\begin{itemize}
    \item \textbf{Branches}: Predict taken if state is 10 or 11 (weakly or strongly taken)
    \item \textbf{Jumps}: Always predict taken (jumps are unconditional)
    \item \textbf{Misprediction}: Detected in EX stage when predicted direction differs from actual outcome
\end{itemize}

\subsection{BRAM-Compatible Memory}

Both instruction and data memories use synchronous read/write operations compatible with FPGA BRAM:

\begin{itemize}
    \item \textbf{Synchronous Read}: Data available on next clock edge after address is provided
    \item \textbf{Synchronous Write}: Write occurs on clock edge when enable and write enable are asserted
    \item \textbf{BRAM Inference}: Quartus synthesis tools can infer BRAM from this structure
    \item \textbf{Performance}: BRAM provides higher frequency and lower resource usage compared to logic-based memory
\end{itemize}

// Update BTB entry
btb_tag[btb_index_ex]    <= btb_tag_ex;
btb_target[btb_index_ex] <= ex_branch ? ex_branch_target : ex_jump_target;

// Two-bit predictor transitions
case (btb_state[btb_index_ex])
  2'b00: if (ex_branch_taken) btb_state[btb_index_ex] <= 2'b01;
  2'b01: btb_state[btb_index_ex] <= ex_branch_taken ? 2'b11 : 2'b00;
  2'b10: btb_state[btb_index_ex] <= ex_branch_taken ? 2'b11 : 2'b01;
  2'b11: if (~ex_branch_taken) btb_state[btb_index_ex] <= 2'b10;
endcase
\end{lstlisting}

  logic [31:0] actual_target = ex_branch ? ex_branch_target : ex_jump_target;
  if (ex_predicted_taken != actual_taken) begin
    flush_if = 1'b1; flush_id = 1'b1; flush_ex = 1'b1;

  end

\section{Register File Implementation}

The register file implements 32 registers with asynchronous read and synchronous write:

\begin{lstlisting}[language=Verilog, caption=Register File Implementation]
module register_file (
    input  logic        clk,
    input  logic        we,
    input  logic [4:0]  addr_rs1,
    input  logic [4:0]  addr_rs2,
    input  logic [4:0]  addr_rd,
    input  logic [31:0] wdata,
    output logic [31:0] rdata_rs1,
    output logic [31:0] rdata_rs2
);

    logic [31:0] registers [0:31];

    // Register x0 is always zero
    assign rdata_rs1 = (addr_rs1 == 5'b0) ? 32'b0 : registers[addr_rs1];
    assign rdata_rs2 = (addr_rs2 == 5'b0) ? 32'b0 : registers[addr_rs2];

    always_ff @(posedge clk) begin
        if (we && addr_rd != 5'b0) begin
            registers[addr_rd] <= wdata;
        end
    end

endmodule
\end{lstlisting}

\subsection{Key Features}

\begin{itemize}
    \item Register x0 hardwired to zero using combinational logic
    \item Writes to x0 are ignored (check \texttt{addr\_rd != 5'b0})
    \item Asynchronous read (data available immediately)
    \item Synchronous write (on clock edge)
\end{itemize}

\section{ALU Implementation}

The ALU supports 10 operations as specified in the requirements:

\begin{lstlisting}[language=Verilog, caption=ALU Operations]
always_comb begin
    case (alu_op)
        4'b0000: alu_out = op_a + op_b;           // ADD
        4'b0001: alu_out = op_a - op_b;           // SUB
        4'b0010: alu_out = op_a & op_b;           // AND
        4'b0011: alu_out = op_a | op_b;           // OR
        4'b0100: alu_out = op_a ^ op_b;           // XOR
        4'b0101: alu_out = op_a << op_b[4:0];     // SLL
        4'b0110: alu_out = op_a >> op_b[4:0];     // SRL
        4'b0111: alu_out = $signed(op_a) >>> op_b[4:0]; // SRA
        4'b1000: alu_out = ($signed(op_a) < $signed(op_b)) ? 32'b1 : 32'b0; // SLT
        4'b1001: alu_out = (op_a < op_b) ? 32'b1 : 32'b0; // SLTU
        default: alu_out = 32'b0;
    endcase
end
\end{lstlisting}

\subsection{Design Considerations}

\begin{itemize}
    \item Shift operations use lower 5 bits of op\_b for shift amount
    \item Arithmetic right shift (\texttt{SRA}) uses \texttt{\$signed()} for sign extension
    \item Comparison operations return 1 if condition true, 0 otherwise
    \item All operations are synthesizable
\end{itemize}

\section{Control Unit Implementation}

The control unit decodes instructions and generates control signals. The implementation uses a case statement on the opcode field:

\begin{lstlisting}[language=Verilog, caption=Control Unit Structure]
always_comb begin
    // Default values
    reg_write = 1'b0;
    mem_write = 1'b0;
    mem_read  = 1'b0;
    // ... other defaults ...
    
    case (opcode)
        7'b0110011: begin // R-type
            reg_write = 1'b1;
            // Set alu_op based on funct3 and funct7
        end
        7'b0010011: begin // I-type (arithmetic/logical)
            reg_write = 1'b1;
            alu_src_b = 2'b01; // Use immediate
            // Set alu_op based on funct3
        end
        7'b0000011: begin // Load instructions
            reg_write = 1'b1;
            mem_read  = 1'b1;
            mem_to_reg = 2'b01;
            // Set mem_size based on funct3
        end
        // ... other instruction types ...
    endcase
end
\end{lstlisting}

\subsection{Special Cases}

\begin{itemize}
    \item \textbf{LUI}: \texttt{alu\_src\_a = 2'b11} (immediate upper), \texttt{alu\_src\_b = 2'b11} (zero), \texttt{alu\_op = ADD}
    \item \textbf{AUIPC}: \texttt{alu\_src\_a = 2'b01} (PC), \texttt{alu\_src\_b = 2'b01} (immediate), \texttt{alu\_op = ADD}
    \item \textbf{JALR}: Jump target is calculated as \texttt{rs1\_data + imm} (computed directly, not through ALU). The control unit sets \texttt{alu\_src\_a = 2'b10} (PC) and \texttt{alu\_src\_b = 2'b01} (imm) for ALU, but the actual jump target uses \texttt{rs1\_data + imm} from the register file.
    \item \textbf{Shift instructions}: Use immediate[4:0] for shift amount (not full 32-bit immediate)
\end{itemize}

\section{Instruction Memory Implementation}

The instruction memory is implemented as a byte-addressable array:

\begin{lstlisting}[language=Verilog, caption=Instruction Memory]
module imem (
    input  logic [31:0]  addr,
    output logic [31:0]  rdata
);

    parameter MEM_SIZE = 16384;
    parameter ADDR_WIDTH = $clog2(MEM_SIZE);

    logic [7:0] mem [0:MEM_SIZE-1];
    logic [ADDR_WIDTH-1:0] byte_addr;

    initial begin
        integer fd;
`ifdef DEMO_MEM
        $readmemh("../02_test/demo.mem", mem);
`else
        // Prefer server-required file isa.mem; if missing (local), fallback to isa_1b.hex
        fd = $fopen("../02_test/isa.mem", "r");
        if (fd) begin
            $fclose(fd);
            $readmemh("../02_test/isa.mem", mem);
        end else begin
            $display("[IMEM] ../02_test/isa.mem not found. Falling back to ../02_test/isa_1b.hex");
            $readmemh("../02_test/isa_1b.hex", mem);
        end
`endif
    end

    assign byte_addr = addr[ADDR_WIDTH-1:0];
    assign rdata = {mem[byte_addr+3], mem[byte_addr+2], 
                     mem[byte_addr+1], mem[byte_addr]};

endmodule
\end{lstlisting}

\subsection{Byte Ordering}

Instructions are stored in little-endian format (LSB at lower address), matching RISC-V specification.

\subsection{Initialization Logic}

The instruction memory includes fallback logic for local testing:
\begin{itemize}
    \item \textbf{Primary}: Attempts to load from \texttt{../02\_test/isa.mem} (required on server)
    \item \textbf{Fallback}: If \texttt{isa.mem} is not found, loads from \texttt{../02\_test/isa\_1b.hex} (for local testing)
    \item \textbf{Demo Mode}: If \texttt{DEMO\_MEM} is defined, loads from \texttt{../02\_test/demo.mem}
\end{itemize}

\section{Data Memory Implementation}

The data memory supports byte, half-word, and word accesses with proper sign extension. The DMEM module only handles addresses in the range 0x0000\_0000 to 0x0000\_07FF (2KB). Writes to I/O regions are handled separately in the top-level module.

\begin{lstlisting}[language=Verilog, caption=Data Memory Write]
always_ff @(posedge clk) begin
    if (we && byte_addr < MEM_SIZE) begin
        case (mem_size)
            3'b000: begin                                // SB
                mem[byte_addr] <= wdata[7:0];
            end
            3'b001: begin                                // SH
                if (byte_addr+1 < MEM_SIZE) begin
                    mem[byte_addr]   <= wdata[7:0];
                    mem[byte_addr+1] <= wdata[15:8];
                end
            end
            3'b010: begin                                // SW
                if (byte_addr+3 < MEM_SIZE) begin
                    mem[byte_addr]   <= wdata[7:0];
                    mem[byte_addr+1] <= wdata[15:8];
                    mem[byte_addr+2] <= wdata[23:16];
                    mem[byte_addr+3] <= wdata[31:24];
                end
            end
        endcase
    end
end
\end{lstlisting}

\subsection{Write Enable Logic}

In the top-level module, the DMEM write enable is gated to only allow writes to the DMEM address range:

\begin{lstlisting}[language=Verilog, caption=DMEM Write Enable Gating]
assign dmem_we = mem_write && (dmem_addr < 32'h0000_0800);
\end{lstlisting}

This ensures that memory writes to I/O regions (0x1000\_0000 and above) are handled by the I/O write logic, not by the DMEM module.

\subsection{Memory Read with Sign Extension}

The data memory read logic handles sign extension and bounds checking:

\begin{lstlisting}[language=Verilog, caption=Data Memory Read]
always_comb begin
    if (byte_addr >= MEM_SIZE) begin
        rdata = 32'b0;
    end else begin
        case (mem_size)
            // LB: sign-extend byte at byte_addr
            3'b000: rdata = {{24{mem[byte_addr][7]}}, mem[byte_addr]};
            // LH: sign-extend halfword starting at byte_addr (little-endian)
            3'b001: rdata = (byte_addr+1 < MEM_SIZE)
                               ? {{16{mem[byte_addr+1][7]}}, 
                                  mem[byte_addr+1], mem[byte_addr]}
                               : {{16{mem[byte_addr][7]}}, mem[byte_addr], 16'b0};
            // LW: word starting at byte_addr (little-endian)
            3'b010: rdata = (byte_addr+3 < MEM_SIZE)
                               ? {mem[byte_addr+3], mem[byte_addr+2], 
                                  mem[byte_addr+1], mem[byte_addr]}
                               : 32'b0;
            // LBU: zero-extend byte
            3'b100: rdata = {24'b0, mem[byte_addr]};
            // LHU: zero-extend halfword
            3'b101: rdata = (byte_addr+1 < MEM_SIZE)
                               ? {16'b0, mem[byte_addr+1], mem[byte_addr]}
                               : {16'b0, mem[byte_addr], 16'b0};
            default: rdata = (byte_addr+3 < MEM_SIZE)
                               ? {mem[byte_addr+3], mem[byte_addr+2], 
                                  mem[byte_addr+1], mem[byte_addr]}
                               : 32'b0;
        endcase
    end
end
\end{lstlisting}

\section{Top-Level Module Integration}

\subsection{Single-Cycle Module}

The \texttt{single\_cycle} module connects all components:

\begin{itemize}
    \item Instantiates all sub-modules (IMEM, register file, ALU, control unit, DMEM)
    \item Implements immediate generation logic
    \item Implements branch condition evaluation
    \item Implements PC update logic
    \item Manages memory-mapped I/O access
    \item Provides debug outputs (\texttt{o\_pc\_debug}, \texttt{o\_insn\_vld})
\end{itemize}

\subsection{Pipelined Module}

The \texttt{pipelined} module implements the five-stage pipeline with advanced features:

\begin{itemize}
    \item \textbf{Pipeline Registers}: IF/ID, ID/EX, EX/MEM, MEM/WB registers with enable and flush control
    \item \textbf{Forwarding Unit}: Resolves data hazards by forwarding from MEM and WB stages
    \item \textbf{Hazard Detection}: Detects load-use hazards and control hazards
    \item \textbf{Branch Predictor}: Two-bit predictor with 256-entry BTB
    \item \textbf{PC Management}: Handles predicted PC, misprediction correction, and stall/flush
    \item \textbf{Debug Signals}: \texttt{o\_insn\_vld}, \texttt{o\_ctrl}, \texttt{o\_mispred} for performance analysis
\end{itemize}

\subsection{Key Signal Assignments}

\subsubsection{Single-Cycle}
\begin{itemize}
    \item \texttt{o\_insn\_vld = i\_reset}: Instruction valid when not reset
    \item \texttt{o\_pc\_debug = pc}: Debug PC output
    \item PC updates on clock edge: \texttt{pc <= pc\_next}
\end{itemize}

\subsubsection{Pipelined}
\begin{itemize}
    \item \texttt{o\_insn\_vld = wb\_enable}: Instruction valid when instruction completes WB stage (not flushed)
    \item \texttt{o\_pc\_debug = pc}: Current PC in IF stage
    \item \texttt{o\_ctrl = wb\_is\_ctrl \&\& wb\_enable}: Control transfer instruction in WB stage
    \item \texttt{o\_mispred = wb\_mispred \&\& wb\_enable}: Misprediction occurred (propagated to WB)
    \item PC updates on clock edge with stall/flush control: \texttt{pc <= pc\_next} when \texttt{if\_enable}
\end{itemize}

\section{Implementation Challenges and Solutions}

\subsection{Challenge 1: LUI Instruction}

\textbf{Problem}: LUI must load immediate to upper 20 bits, not add to any register value.

\textbf{Solution}: Use \texttt{alu\_src\_a = 2'b11} (immediate upper) and \texttt{alu\_src\_b = 2'b11} (zero), then ADD operation results in just the immediate value.

\subsection{Challenge 2: Memory-Mapped I/O}

\textbf{Problem}: Need to route memory accesses between DMEM and I/O regions.

\textbf{Solution}: Implement address decode logic in LSU to determine access type and route accordingly.

\subsection{Challenge 3: Sign Extension for Loads}

\textbf{Problem}: LB and LH must sign-extend, while LBU and LHU must zero-extend.

\textbf{Solution}: Use different \texttt{mem\_size} codes (3'b000 for LB, 3'b100 for LBU) and handle sign extension in read logic.

\subsection{Challenge 4: Misaligned Address Handling}

\textbf{Problem}: Addresses for word access must be word-aligned (LSB bits = 00).

\textbf{Solution}: Truncate address to word boundary using \texttt{word\_addr = \{addr[ADDR\_WIDTH-1:2], 2'b00\}}.

\subsection{Challenge 5: Pipeline Hazards (Pipelined Processor)}

\textbf{Problem}: Data hazards occur when instructions depend on results from previous instructions still in pipeline.

\textbf{Solution}: Implement forwarding unit to forward data from MEM and WB stages to EX stage, eliminating most data hazards without stalling.

\subsection{Challenge 6: Load-Use Hazards (Pipelined Processor)}

\textbf{Problem}: Load instructions require data from memory, which is not available until MEM stage, causing data dependency.

\textbf{Solution}: Detect load-use hazards in hazard detection unit and stall pipeline for one cycle, inserting bubble in EX stage.

\subsection{Challenge 7: Control Hazards (Pipelined Processor)}

\textbf{Problem}: Branch and jump instructions change control flow, but target address is not known until EX stage.

\textbf{Solution}: Implement branch predictor with BTB to predict branch direction and target in IF stage, flush pipeline when misprediction detected.

\subsection{Challenge 8: Branch Prediction Accuracy}

\textbf{Problem}: Static prediction (always not-taken) has low accuracy, reducing performance.

\textbf{Solution}: Implement two-bit dynamic predictor that learns branch behavior and adapts prediction based on history, achieving higher accuracy than static prediction.

\subsection{Challenge 9: BRAM Compatibility}

\textbf{Problem}: Memory must be synthesizable to BRAM for higher frequency and lower resource usage.

\textbf{Solution}: Use synchronous read/write operations with proper enable signals, allowing Quartus to infer BRAM from RTL code.
